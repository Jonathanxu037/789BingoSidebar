1. 背景与目标

在游戏过程中提供快捷入口，方便用户使用常用功能并快速切换其他游戏；用户在每款游戏内首次点击退出时自动展开侧边栏展示推荐内容，减少退出后的流失。

  • 提升游戏间切换率与推荐后继续投注。
  • 降低"退出即流失"比例。
  • 为活动提供游戏内曝光位，并将流量导入活动详情页或指定页面。

2. 名词说明

名词说明
浮标游戏页右上角的 789bingo Logo 圆形按钮，侧边栏收起时的唯一入口。
侧边栏右侧窄版纵向面板，包含快捷功能、Mini Banner、推荐游戏。
自动展开机会每进入一款游戏获得 1 次；首次点击退出时消耗。
手动展开 / 自动展开用户点击浮标展开 / 首次退出时系统展开。

3. 前端需求（H5 游戏页）

本章仅描述功能与交互逻辑；浮标、侧边栏及各模块的视觉样式、尺寸与动效均以设计师设计稿为准。

3.1 浮标

  • 默认状态仅显示浮标；后台"启用游戏快捷侧边栏"关闭时不显示。
  • 点击浮标手动展开侧边栏；侧边栏展开期间浮标隐藏，收起后恢复。

3.2 侧边栏结构

右侧窄版纵向布局，展开后保留主要游戏画面。从上到下：

  1. 标题栏：平台品牌标识。
  2. 收起按钮：点击收起侧边栏并恢复浮标。
  3. 快捷功能：Home、Deposit、Reload，点击分别跳转首页 / 充值页 / 刷新余额；三者均须先完成当前游戏结算与余额同步（见 3.8）。
  4. Mini Banner：详见 3.7。
  5. 推荐游戏：2 列布局，首屏每列展示 3 个完整 Icon + 第 4 个部分露出（2 × 3.5）；区域支持上下滑动。仅展示正方形 Icon，不展示名称、类别、Provider、Hot/New/Jackpot 等标签。

推荐列表数据规则：按后台排序；过滤维护 / 下架 / 不可进入的游戏及当前正在玩的游戏；取前 N 个（N = 后台展示数量）。不足时按实际数量展示。

3.3 展开 / 收起

  • 展开方式：① 点击浮标手动展开；② 每款游戏内首次退出时自动展开（见 3.4、3.5）。
  • 收起方式：① 收起按钮；② 点击侧边栏外的游戏区域（退出确认显示期间除外）。

3.4 首次退出自动展开

  • 游戏内退出入口、退出操作沿用平台现有实现，本需求不做调整。
  • 退出二次确认页面不做任何修改：用户在前台点击退出时弹出的二次确认页面，其样式、文案、按钮及交互均保持当前线上版本，本需求不涉及。
  • 用户在当前游戏内首次触发退出时，在平台现有退出流程基础上自动展开侧边栏；用户可直接点击推荐游戏切换。

3.5 退出自动展开规则

场景系统行为
进入游戏后首次点击退出（机会可用）按平台现有流程触发退出确认，同时自动展开侧边栏；机会标记为已使用。若侧边栏已手动展开，则保持展开并转为"自动展开"状态。
自动展开后点击推荐游戏关闭退出确认，退出当前游戏并直接进入所选游戏。
自动展开后用户取消退出同时收起侧边栏，继续停留当前游戏。
自动展开后仅点收起按钮收起侧边栏，退出确认保留，由用户继续选择。
自动展开后用户确认退出按平台现有流程正常退出。
同一游戏内再次点击退出按平台现有流程退出，不再自动展开。
进入新游戏 / 从大厅重新进入自动展开机会重置为可用。
手动展开后再关闭不消耗、不影响自动展开机会。
后台关闭"退出时自动展开"退出按平台现有流程执行；浮标与手动展开不受影响。

自动展开机会以"用户 + 当前游戏"为维度记录。用户在当前游戏内刷新页面（含断线重连后重新加载）不影响该机制：已使用的机会不会因刷新而重置，未使用的机会刷新后仍保留；仅在切换至其他游戏或从大厅重新进入游戏时重置。

3.6 游戏切换待研发确认三方游戏跳转结算机制

切换逻辑

  1. 用户点击推荐游戏列表中的游戏 Icon → 锁定点击（仅处理第一次有效点击）。
  2. 直接退出当前游戏，并跳转进入所选游戏（不经过大厅）。
  3. 进入新游戏后，侧边栏刷新自动展开机会：用户在新游戏内首次点击退出 / 关闭游戏时，将再次自动展开侧边栏。
  4. 启动失败：提示游戏暂时不可用，侧边栏保持展开，解锁可重新选择。
  5. 所选游戏已维护 / 下架（侧边栏列表未及时同步）：不退出当前游戏，弹窗提示"该游戏当前维护中"，同时刷新侧边栏推荐游戏列表；用户仍停留在当前游戏中，游戏不中断。

余额结算与同步待研发确认三方游戏跳转结算机制

  1. 退出当前游戏时，按平台现有规则对该第三方游戏的用户余额与平台余额进行结算同步。
  2. 进入新游戏时，按平台现有规则将用户账户余额同步至新游戏对应的第三方供应商。
  3. 须在当前游戏结算同步完成后，再发起新游戏的余额同步与启动；任一环节失败按"启动失败"处理，并确保用户余额不丢失、不重复。

当前局未结算时的切换待研发确认三方游戏跳转结算机制

部分游戏在用户已投注、当前局尚未结算时点击推荐游戏，为避免第三方游戏平台与我方平台的用户余额不一致，按以下流程处理：

  1. 保持当前游戏画面，显示 loading 蒙层（半透明，用户可透过蒙层看到当前局的结算过程与结果），期间屏蔽其他操作及重复点击。
  2. 等待当前局结算完成。
  3. 结算完成后，按平台现有规则将第三方平台余额与我方平台账户余额结算同步。
  4. 同步完成后，退出当前游戏并跳转进入所选新游戏，将结算后的用户账户余额同步至新游戏的第三方供应商。
  5. 任一环节失败（结算超时、同步失败、新游戏启动失败）：关闭蒙层，提示游戏暂时不可用，用户留在当前游戏中，余额以同步后的结果为准。

3.7 Mini Banner

  • Mini Banner 仅展示 1 个活动，不轮播；内容由后台配置（见 4.2）。
  • 展示图片为后台为该活动单独上传的 Mini Banner 图，不使用活动原有 Banner。
  • 点击后先完成当前游戏结算与余额同步（见 3.8），再按后台配置的跳转方式跳转（二选一）：
    • 选择活动：跳转至所选活动的详情页。
    • 自定义跳转链接：直接跳转至该链接地址。
  • 以下情况隐藏 Mini Banner 区域：后台"是否展示"关闭；未上传图片或未配置跳转目标；跳转方式为"选择活动"且活动已下架 / 结束；图片加载失败。

3.8 离开当前游戏的余额保障（通用规则）待研发确认三方游戏跳转结算机制

凡是会关闭当前游戏、从当前游戏直接跳转离开或需要读取最新余额的操作，均须先完成当前游戏结算，并统一第三方游戏平台与我方平台的用户账户余额，遵循 3.6 中"余额结算与同步"及"当前局未结算时的切换"规则，包括但不限于：

触发操作离开后去向
点击推荐游戏进入所选新游戏
快捷功能 Home平台首页
快捷功能 Deposit充值页
快捷功能 Reload刷新并展示结算同步后的最新余额
点击 Mini Banner活动详情页 / 后台配置的跳转链接
自动展开后用户确认退出 / 关闭游戏按平台现有退出去向
  1. 离开前先判断当前局是否已投注未结算：是则显示 loading 蒙层，展示当前局结算过程，结算完成后再继续。
  2. 按平台现有规则完成第三方平台与我方平台的余额结算同步后，才执行跳转。
  3. 如目标为新游戏，再将结算后的余额同步至新游戏的第三方供应商。
  4. 任一环节失败：关闭蒙层并提示，用户留在当前游戏中，不执行跳转；余额以同步结果为准，确保不丢失、不重复。
  5. 处理期间屏蔽侧边栏及游戏内的其他离开操作，避免并发触发多次结算。

4. 后台需求

菜单路径：活动配置 → 游戏快捷侧边栏管理。页面顶部提供币别选择，配置按币别站点独立生效。

  • 底部操作栏：页面底部吸底固定显示"重置"与"保存配置"按钮，无论页面如何滚动均可随时点击；操作栏附提示"修改后需点击'保存配置'才会在前台生效"。
  • 保存配置：提交当前币别下全部配置，保存成功后给出提示，新进入游戏的用户读取新配置。
  • 重置：放弃未保存的修改，恢复为上次保存的配置。

4.2 Mini Banner 配置

配置项说明
是否展示开关，默认开。
跳转方式（必填）单选，二选一：选择活动 / 自定义跳转链接，默认选择活动。
选择活动跳转方式为"选择活动"时必填；下拉单选，选项为当前平台已有且展示中的活动；点击跳转该活动详情页。
跳转链接跳转方式为"自定义跳转链接"时必填；需以 http(s):// 开头，保存时校验格式；点击直接跳转至该地址。
Mini Banner 图（必填）为该活动单独上传在 Mini Banner 位置展示的图片；支持预览、重新上传、删除。图片尺寸、格式及大小规格待设计师确认设计稿后同步确认。

"是否展示"开启时，未上传图片、或未填写当前跳转方式对应的必填项，不允许保存并给出提示。跳转方式为"选择活动"且该活动在平台下架 / 结束后，前台自动隐藏 Mini Banner，后台需重新配置。

4.3 推荐游戏配置

  • 展示数量：整数 1–30，默认 10。
  • 添加游戏：弹窗支持按名称搜索、多选；已添加的游戏置灰不可选；确认后追加到列表末尾。
  • 列表字段：
    • 排序，附前台位次提示："前台第 N 位" / "超出展示数量"。
    • 游戏图标、游戏名称、游戏类型。
    • 游戏状态：正常 / 维护中 / 已下架，后两者附"前台不展示"提示。
    • 排序调整（上移 / 下移）、删除。
  • 前台严格按后台排序展示，并自动跳过不可进入的游戏；位次提示需与此规则一致。

5. 异常处理

场景处理
列表未同步，用户点击了已维护 / 下架的游戏点击时校验游戏状态：弹窗提示"该游戏当前维护中"；刷新侧边栏推荐游戏列表（剔除该游戏，后续依次前移）；不退出、不刷新当前游戏，用户保持在当前游戏中；自动展开机会状态不变。
游戏下架 / 维护 / 不可进入不展示该游戏，后续游戏依次前移。
推荐游戏不足 7 个按实际数量展示；为 0 时显示无可用游戏提示。
游戏启动失败Toast 提示游戏暂时不可用，侧边栏保持展开，解除点击锁。
推荐列表加载失败保留 Home / Deposit / Reload / Banner；推荐区隐藏或显示加载失败及重试入口。
切换时当前局已投注未结算待研发确认三方游戏跳转结算机制显示 loading 蒙层并展示当前局结算过程；结算完成 → 余额同步 → 进入新游戏并同步结算后余额。结算超时的时长阈值待定。
连续点击多个游戏仅处理第一次有效点击，切换完成或失败前其余点击无效。
Mini Banner 图片加载失败 / 活动已下架隐藏 Mini Banner 区域，其余模块正常展示。
配置接口失败不展示浮标，游戏正常运行，退出按平台现有流程执行。

7. 核心流程

  • 正常使用：游戏中 → 点击浮标 → 展开侧边栏 → 使用快捷功能 / 切换游戏。
  • 退出推荐：进入游戏 → 首次退出 → 自动展开侧边栏 → 点击推荐游戏 → 进入新游戏。
  • 拒绝推荐：首次退出 → 自动展开 → 用户取消退出 / 收起侧边栏 → 再次退出 → 直接正常退出。

8. 验收标准

  • 每款游戏内自动展开最多触发 1 次，刷新页面不重置；切换 / 从大厅重新进入游戏后可再次触发。
  • 手动展开并关闭后，首次退出仍会自动展开。
  • 推荐区首屏为 2 列 × 3.5 个，可滑动；无文字或标签。
  • 视觉样式与动效与设计稿一致。
  • 前台展示顺序、数量、过滤结果与后台位次提示一致。
  • 快速连点多个推荐游戏只触发一次切换。
  • 推荐游戏、Home、Deposit、Reload、Banner、确认退出均在当前游戏结算及余额同步完成后才执行；当前局未结算时先展示结算过程；前后余额一致。待研发确认三方游戏跳转结算机制
  • Mini Banner 仅展示后台配置的 1 个活动图片、不轮播；按后台跳转方式跳转活动详情页或自定义链接（二选一）。
  • 后台保存后，新进入游戏的用户读取到新配置。

9. 待确认事项

  1. 待研发确认三方游戏跳转结算机制：各第三方供应商在退出 / 跳转时的结算与余额同步方式、未结算局的判断与等待机制、失败回滚方案（涉及 3.6、3.8 及相关异常处理）。
